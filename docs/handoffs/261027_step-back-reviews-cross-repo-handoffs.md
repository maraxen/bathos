## 2. Praxia Integration Handoff

### 2.1 `PROJECT_STATUS.advisor.md` ("End / reconsider" Column) Integration

#### Objective
Enable the researcher's global portfolio dashboard (`PROJECT_STATUS.advisor.md`), generated by Praxia's `scripts/projects/project_status.py`, to automatically reflect real-time campaign step-back statuses and escalation holds.

#### Operational Interface
`scripts/projects/project_status.py` queries `bth stepback brief <campaign-id>` or the FastMCP tool `stepback_brief(campaign_id)` and populates the `"End / reconsider"` table cell for each project.

#### Contracted Tag Syntax & Semantics
Per locked user decision (`261027_step-back-reviews`), the `"End / reconsider"` cell in `PROJECT_STATUS.advisor.md` surfaces tags **only for campaigns at Level $\ge 1$** (`format_project_status_entry(campaign_id, include_nominal=False)` / `stepback_brief(campaign_id)["advisor_status_entry"]`), keeping Level 0 nominal campaigns concise/blank in the advisor table while retaining `[NOMINAL: N runs, pass rate X.XX]` in full `bth stepback brief` outputs:

| Escalation Level | Tag Syntax (`include_nominal=True`) | `PROJECT_STATUS.advisor.md` Cell (`include_nominal=False`) | Meaning |
|---|---|---|---|
| **Level 0 (Nominal)** | `[NOMINAL: N runs, pass rate X.XX]` | `""` *(blank/concise)* | Campaign operating cleanly within nominal variance; no triggers active. |
| **Level 1 (Advisory)** | `[ADVISORY L1: <trigger_name> active; review recommended]` | `[ADVISORY L1: <trigger_name> active; review recommended]` | Single trigger firing (e.g. `repeated_marginal`, `near_bound`); single blind reviewer dispatched. |
| **Level 2 (Hold)** | `[HOLD L2: <trigger_reason>; review <review_id> recommends <rec>]` | `[HOLD L2: <trigger_reason>; review <review_id> recommends <rec>]` | Hard-floor veto, dissent, or multiple triggers; 3-persona committee dispatched; conclusion downgraded to `confounded`. |
| **Level 3 (Escalation)** | `[ESCALATE L3: Human Chair disposition required; <reason>]` | `[ESCALATE L3: Human Chair disposition required; <reason>]` | Critical anomaly or human referral; autonomous progress awaits Human Chair. |

#### Implementation in `scripts/projects/project_status.py`
```python
def extract_stepback_status_snippet(campaign_id: str, catalog_dir: Path | None = None) -> str:
    """Extract formatted snippet for PROJECT_STATUS.advisor.md 'End / reconsider' column."""
    import subprocess
    import json
    
    cmd = ["bth", "stepback", "brief", campaign_id]
    res = subprocess.run(cmd, capture_output=True, text=True)
    if res.returncode != 0:
        return "[UNKNOWN: stepback query failed]"
    
    # Parse brief section 7: Project Status Matrix Entry
    for line in res.stdout.splitlines():
        if line.strip().startswith("[") and (
            "NOMINAL" in line or "ADVISORY L1" in line or "HOLD L2" in line or "ESCALATE L3" in line
        ):
            return line.strip()
    return "[NOMINAL: uninitialized]"
```

### 2.2 Automated Blind Reviewer & Committee Dispatch Workflow

#### Objective
Orchestrate autonomous, un-coerced step-back reviews by dispatching Praxia subagents that strictly comply with the **Blind Reviewer Protocol** (Requirement R2 and research doc §5, §8).

#### Dispatch Discipline & Attribution Barrier
When `bth stepback trigger` or Praxia's OODA monitor detects an active trigger:
1. **Attribution Separation**:
   - The coordinator inspects the campaign author set:
     $$\mathcal{A}_{\text{forbidden}} = \{\text{creator}, \text{run authors}, \text{git committers during window}\}$$
   - Praxia must dispatch an independent reviewer role (e.g. `praxia_critic`, `specminer`, or `outsider_auditor`) whose runtime conversation ID and agent identity are **not** in $\mathcal{A}_{\text{forbidden}}$.
2. **Context Masking (Blindness to Advocacy)**:
   - The dispatched reviewer prompt **must NOT** receive the doing agent's summary reports, chat logs, or narrative rationalizations.
   - The prompt provides only primary catalog identifiers:
     - Campaign ID (`campaign_id`)
     - Member run list (`bth run ls --campaign-id <id>`)
     - Pre-registered sidecar paths (`*.bth.toml`)
     - Registered claim path (`claim.bth.toml`)
3. **Mandatory Domain Diagnostic Checks**:
   The reviewer dispatch prompt explicitly instructs the subagent to evaluate:
   - *Unit of Independence*: Verify simulation replicates are pooled/concatenated as samples of one ensemble, not treated as independent experiments that must each converge (§9 #1).
   - *Checks That Cannot Fail*: Identify tautological controls, census fields locked to 0, and metrics sharing formulas with optimization objectives (§9 #2).
   - *Variance Inflation*: Check between-build vs within-build variance and paired vs unpaired baseline floors (§9 #3).
4. **Handling `REVIEWER_CONFLICT_OF_INTEREST`**:
   If a review submission returns `BathosErrorCode.REVIEWER_CONFLICT_OF_INTEREST`:
   - Praxia's router catches error code `STEPBACK_REVIEWER_CONFLICT_OF_INTEREST`.
   - The review is logged as non-discharging.
   - The router automatically re-dispatches to an alternate, authenticated reviewer subagent.

## 3. Maraxiom Integration Handoff

### 3.1 Private Review Page Generation (`mrx review build`)

#### Objective
When a campaign escalates to **Level 3 (Human Chair Escalation)**, Maraxiom generates an interactive, private, provenanced review page for the human committee chair.

#### Invocation & Recipe Contract
Upon Level 3 escalation, the coordinator generates `.review.toml` in the campaign root and triggers `mrx review build`:

```toml
# .review.toml
[review]
campaign_id = "6f792f0d-2b7e-4a11-8a03-9128d542d174"
title = "Level 3 Step-Back Escalation: sp98-gap-augmented-testbed"
escalation_level = 3
lead_reviewer = "critic_agent_1"
output_path = "reports/reviews/stepback_6f792f0d.html"

[review.components]
trajectory_chart = true
near_bound_distribution = true
plateau_regression = true
dissent_cards = true
advisor_brief = true
```

Command:
```bash
mrx review build --campaign-id 6f792f0d --recipe .review.toml
```

### 3.2 Visual Component Mapping
The generated Maraxiom page incorporates four deterministic SVG/HTML components:

1. **Trajectory & Outcome Sequence Card**:
   - Visualizes run sequence $R = [r_1 \dots r_N]$ with outcome coloring (`pass` = green, `marginal` = yellow, `fail` = red, `confounded` = purple).
   - Highlights the sliding window $W_5$ and marks near-bound hits.
2. **Boundary Proximity Scatter Plot**:
   - Plots scalar metric values $y_i$ against decision boundary $B$.
   - Draws shaded margin bands for $\epsilon = 0.10 \times |B|$ and flags runs with $d_i \le 1.0$.
3. **Moving Slope Plateau Regression**:
   - Displays OLS regression line over the recent $n=6$ runs with relative slope $\bar{\beta}_{\text{rel}}$ and coefficient of variation $CV$.
4. **Minority Dissent Callouts**:
   - Renders dissenting reviews from the immutable `dissents` array in high-contrast quote cards with direct links to cited counter-evidence (`run:<id>`).

### 3.3 Inviolable Ethical Invariant: Exit Code 3 / LAUNDERING Prevention
In accordance with Maraxiom's core ethics gate:
- If a campaign review record has a dimension score of $s_5 = 1$ (fatal confound / unmitigated data leakage) or notes an unmitigated fatal confound, `mrx review build` **must never** emit a public or polished presentation deck.
- Attempting to publish or promote a review page that whitewashes an active Level 3 hold must exit immediately with **Exit Code 3 (`LAUNDERING`)**.

## 4. Contemplex Integration Handoff

### 4.1 Linking Brainstorming Sessions to Path B Open-Analysis Reviews

#### Objective
Connect Contemplex's 4-Phase ideation substrate to `bathos` Path B qualitative modes, ensuring that divergent exploration and adversarial convergence feed directly into provenanced step-back records.

#### Mode & Phase Mapping

| Path B Cognitive Mode | Contemplex Phase & Technique | Operational Intent |
|---|---|---|
| **`advisor`** | Phase 1 (Problem Framing) + Socratic Forcing Beat | Interrogate core hypothesis, identify unstated assumptions, ask "what would change your plan?". |
| **`pre_mortem`** | Phase 3 (Convergence) + Prospective Hindsight Pre-Mortem | Assume total project failure at 6 months; map backward to identify root causes and active red flags. |
| **`so_what`** | Phase 4 (Synthesis) + INVEST Gate Evaluation | Evaluate whether ideal confirmation changes any actual scientific or strategic decision. |
| **`outsider`** | Phase 2 (Divergence) + Lateral Thinking / Perspective Shift | Strip away internal terminology and assess scientific cogency from elementary first principles. |
| **`steelman_stop`** | Phase 3 (Convergence) + Adversarial Elimination Ladder | Construct the strongest evidence-backed prosecutor case for terminating the campaign immediately. |

### 4.2 Provenance Binding & Ingestion
When a Contemplex brainstorming session concludes:
1. The session records its final decision via `brainstorm_record_decision`.
2. The summary and cited catalog runs are formatted into the Path B JSON payload.
3. The review is registered with explicit metadata linkage:
   ```bash
   bth stepback record <campaign-id> \
     --path open_analysis \
     --mode pre_mortem \
     --recommendation PIVOT \
     --text "$CONTEMPLEX_SYNTHESIS_TEXT" \
     --evidence "$CONTEMPLEX_CITED_RUNS" \
     --reviewer-id "$CONTEMPLEX_FACILITATOR_ID"
   ```
4. DuckDB schema v19 stores `contemplex_session_id` inside `stepback_reviews.metadata`.
